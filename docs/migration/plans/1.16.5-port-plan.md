## Milestones (each ends with `./gradlew build` green; M3 onwards also the client + server test suites)

1. **M0 Toolchain.** Gradle/ForgeGradle/Forge/mappings bump; project resolves and all errors are listed (counted by category).
2. **M1 Rendering (the old 1.15 step).** `GlStateManager` use (47 files) and `TileEntityRenderer` (11) / item-stack renderers (2)
   move to `MatrixStack` + `IRenderTypeBuffer`; entity renderers, particles, overlay code.
3. **M2 Core API.** `TileEntity.read(BlockState, CompoundNBT)`, `ActionResultType` returns from `onBlockActivated` /
   `onItemRightClick` / `onItemUse`, `ITickableTileEntity` unchanged, block/item property changes, `ContainerType` / capability /
   network details, loot and recipe JSON format changes, tags, `ModelLoader`/baked model changes.
4. **M3 Boots and passes tests.** Client boots, resource audit 0 failures, behavior tests that do not depend on dimension/worldgen pass.
5. **M4 Dimension.** Spectre becomes a data-driven dimension (dimension type + chunk generator codec; `ModDimension` and
   `RegisterDimensionsEvent` are gone); teleporter/coremod retarget; Spectre cube lookup, tests.
6. **M5 Worldgen.** Bean sprout / lotus / ancient furnace / glowing mushroom via `BiomeLoadingEvent`; Peace Candle church pool
   (data-driven template pools); structure NBT load.
7. **M6 Coremods.** Retarget the 15 JS transformers to 1.16.5 class/method names; `CoremodTests` pass.
8. **M7 Full verification.** Client suite, `runServer` suite, `./gradlew build`, then hand-test list for the owner.

## Method per milestone

- Compile errors are grouped, the real 1.16.5 signature is read with `javap` from the mapped jar (CLAUDE.md rule), then fixed in bulk by
  category (scripted where purely mechanical), not file by file.
- Behavior is matched to the 1.14.4 port; anything that looks wrong is checked against the 1.14.4 source first.
- `TESTING_CHECKLIST.md` and `PORTING_PLAN.md` are updated in the same pass as the code.
- Findings are added to `docs/migration/versions/mc-1.16.md` work log and the pitfall catalog.

## Status (2026-10-11)

M0-M7 are done in code: the branch compiles, `./gradlew build` passes, the client suite (333 passed / 1 skipped, same as 1.14.4), the dedicated-server suite (333 / 1 skipped) and the resource audit (0 failures) are green, all 28 GUIs open without errors, and a new world and a reopened world both load with the Spectre dimension. **Not verified by anything automated (needs the owner's eyes):** how the new `MatrixStack` renderers, the GUI interactions (the 28 layouts were compared screenshot-by-screenshot with 1.14.4 and match), the Spectre sky/fog, the item/armor recolor and rain-suppression visuals actually look; natural worldgen and the Peace Candle village church; and everything in `TESTING_CHECKLIST.md` that is visual.

Update 2026-10-11: two new dev-only automated passes now cover part of that list - `RT_AUTOTEST_SCENES=true` (render screenshots of every renderer/item scene; found and fixed the black Biome Radar crystal) and `RT_AUTOTEST_CLICKS=true` (28 GUIs, every button clicked, text fields saved: 0 failures). Still human-only: slot interactions, natural worldgen, Peace Candle church, Time Accelerator icons / Eclipsed Clock label.

Update 2026-10-11 (worldgen tests): deterministic `worldgen.*` tests now cover Glowing Mushroom and Peace Candle church generation. They found two real bugs in 1.16.5 natural Glowing Mushroom generation/survival (fixed: soil-only worldgen rule, mushroom light 15 -> 12; see checklist #395). Real default-world check on a production server: 70 of 1,687 chunks contain mushrooms (was 0).

Known issues / follow-ups:
- (Decided: leave as is, backlog Q14.) Reopening a world that contains the Spectre dimension shows vanilla's "Worlds using Experimental Settings" backup prompt (any extra dimension triggers it in 1.16.5; registering the dimension from code instead of datapack JSON removed the prompt on world *creation* only). Possible fix: coremod `ServerWorldInfo.getLifecycle` (backlog Q14).
- Forge 36.2.40+ needs ForgeGradle 5/6; this branch is pinned to 36.2.39 (see `versions/mc-1.16.md`).
- The Peace Candle church swap matches vanilla's `plains_temple_4` piece by its `toString`; verify in a real plains village.
- Static registries (block entity / entity weak sets, Advanced Redstone Torch + relight maps) are now created with `util/WeakSets` (synchronized) and iterated via `WeakSets.snapshot`; test `registry.weak_sets_survive_concurrent_add_remove_and_iteration`.
- Coremods now match MCP and SRG names and were verified on a production Forge 1.16.5 server (backlog Q13); the client suite and render scenes also ran on a production client (including new Light Redirector and Magic Hood scenes).

## Risks

- Dimension and worldgen rewrite (M4/M5) is the largest unknown; keep them last so M1-M3 can be validated first.
- Some client-side hooks the coremods rely on (`GameRenderer`, `ItemRenderer`, `BlockRendererDispatcher`) were reshaped by the `MatrixStack` change.
- The 1.14.4 branch still has an open owner playtest list (backlog Q7); fixes found there must be cherry-picked forward.
