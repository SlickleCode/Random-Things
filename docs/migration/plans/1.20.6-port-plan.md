# 1.20.6 port plan (NeoForge 20.6.141)

Branch `1.20.6`, cut from `1.20.1` (`fec80ba`) on 2026-10-20. Owner decisions (2026-10-20): **NeoForge 20.6.141** (not Forge 50.2.10), JDK 21 (Temurin, `~/.jdks/temurin-21`). Every adaptation and API surprise: [`docs/project/api-gotchas-1.20.6.md`](../../project/api-gotchas-1.20.6.md).

## Toolchain

NeoGradle `net.neoforged.gradle.userdev` 7.0.192 (needs **Gradle 8.13**), JDK 21 toolchain, Mojang names, `implementation 'net.neoforged:neoforge:20.6.141'`. The run config is the NeoGradle `runs {}` block; `mods.toml` is `META-INF/neoforge.mods.toml`. **Production = Mojang names** (NeoForge 20.5+ does not reobfuscate, no `reobfJar`): there is no SRG production variant of the suites any more; the `prod-jar-check` skill needs only a real NeoForge install of the built jar (not set up here, see "Still open").

## Still open

- Known unrelated oddity seen in the render scenes (also present on 1.20.1): the Blazing Fire block draws as a solid cube in the block scene.
- Mirror-back candidates for older branches: `checkBurnOut` name in `FireBlockTransformer.js`; the unregistered `EclipsedClockAnimationMessage`; `NbtUtils.loadUUID(compound.getCompound(..))` should be `compound.get(..)` on 1.20.1 (`createUUID` returns an int array there too).
- `behavior.portkey...teleports_the_picker_upper` failed once (landed at y=99, three blocks under the floor): not reproducible in 6 further full server runs (plus 5 earlier ones). That failing run was the first one after a run killed by the 60 s server watchdog (the village-assembly test needs more than 60 s per tick on this machine), which left test debris in the reused `run/RTServerTest` world below the cleared area; the Portkey landing spot is random among every supporting block in the 5x5 column. So: stale world after an aborted run, not a port bug. Keep `max-tick-time=-1` in `run/server.properties` and delete `run/RTServerTest` after an aborted run; the test now prints the landing column if it ever fails again.
