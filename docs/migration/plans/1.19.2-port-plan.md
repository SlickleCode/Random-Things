### What M1 changed (beyond the renames)

- **Forge 43.5.2 API is the 1.19.4-style one** (checked with `javap` on the universal jar, not from memory): `net.minecraftforge.event.level.*`, `TickEvent.LevelTickEvent` (`event.level`), `LivingEvent.LivingTickEvent`, `getEntity()` instead of `getPlayer()/getEntityLiving()`, `getLevel()` instead of `getWorld()`, `RegisterColorHandlersEvent`, `ModelEvent.RegisterAdditional`, `InputEvent.Key/MouseButton.Pre`, `ScreenEvent.Render.Post/MouseButtonPressed.Pre`, `ServerChatEvent.Submitted` (use `getRawText()`).
- **Registration:** one `RegisterEvent` subscriber in `RandomThings.RegistryEvents` dispatches on the registry key; the `Mod*` register methods take an `IForgeRegistry<T>` and call `register(name, value)` (no `setRegistryName`). `@ObjectHolder` is field-level only, with `registryName` + full `randomthings:` id; the class-level holder is gone. `getRegistryName()` is replaced by `util/RegUtil.id(...)` (block/item/fluid/entity type/block entity type/effect/enchantment).
- **Global loot modifier** (Magnetic) is codec-based now (`MagneticLootModifier.CODEC`, registered at `GLOBAL_LOOT_MODIFIER_SERIALIZERS`); the JSON already had `type`.
- **Biomes:** no `BiomeDictionary` and no registry name on `Biome`. `util/BiomeUtil` resolves a biome instance's holder through the client/server `RegistryAccess` (falling back to `ForgeRegistries.BIOMES`) and reports the old dictionary type names from `forge:is_*` / `minecraft:is_*` biome tags. Feature injection is data-driven: `data/randomthings/forge/biome_modifier/*.json` (`forge:add_features`, `#minecraft:is_overworld`) replaces the `BiomeLoadingEvent` hook.
- **Hoe tilling** of Fertilized Dirt now uses `BlockEvent.BlockToolModificationEvent` (`HOE_TILL`, `setFinalState`) instead of `UseHoeEvent`.
- **Fluids:** `FluidAttributes` -> `IClientFluidTypeExtensions.of(fluid)` / `FluidStack.getDisplayName()`.
- **Client:** `IClientBlockExtensions` / `IClientItemExtensions.getCustomRenderer()`; `NetworkHooks.openScreen`; `sendSystemMessage`; `player.commandUnsigned(...)` for the autotest commands; world creation through `createWorldOpenFlows()` + `WorldPresets.createNormalWorldFromPreset`; resource reads through `Optional<Resource>`.
- **Spectre chunk generator:** new `RandomState`/`StructureManager` signatures; `withSeed`/`climateSampler` are gone.
- `Random` -> `RandomSource` in every block/feature override; `quickMoveStack` is abstract now (EMPTY default added to the containers that lacked it).

### Server boot (2026-10-15)

`RT_AUTOTEST=true RT_AUTOTEST_EXIT=true ./gradlew runServer`: the dedicated server boots and the dev suite gives **357 passed / 0 failed / 2 skipped (of 359)** (the 2 environment skips are the same as on 1.16.5/1.18.2). Found and fixed on the way:

- `ModFeatures.placed()` NPE while encoding the built-in registry (the `@ObjectHolder` feature fields were null): the holder's registry name for features is `minecraft:worldgen/feature`, and `placed()` now reads the feature from `ForgeRegistries.FEATURES` and fails loudly if it is missing.
- `dimension_type/spectre.json` needs `monster_spawn_light_level` and `monster_spawn_block_light_limit` in 1.19.
- Coremods (checked with `docs/migration/tools/CoremodCheck.java` against the 1.19.2 mapped jar, then the suite): `SpawnPlacementTransformer` descriptor `Random` -> `RandomSource`; `FireBlockTransformer` now matches `INVOKEINTERFACE RandomSource.nextInt` and redirects `getFireTickDelay(RandomSource)` (`AsmHandler.fireTickCooldown` takes a `RandomSource`); `BlockRendererDispatcherTransformer` targets the Forge overload `renderBatched(..., RandomSource, ModelData, RenderType, boolean)V` and returns with a plain `RETURN`; `VertexLighterFlat` is gone from Forge 43 and its only hook (placeholder tint 12340) is unused, so the transformer was deleted (`AsmHandler.modBlockLight` is now dead code).
- All 14 remaining transformers report `ok` in CoremodCheck except `BlockRendererDispatcherTransformer` and `SpawnPlacementTransformer` before the fixes above (re-run it after the next edit); the render-side ones (`ArmorLayer`, `MagicHood`, `ItemRenderer`, `RenderType`, `LevelRenderer`, `Player`) are only checked offline - no client has run yet.

### M2 result (2026-10-17)

- `WorldgenTests` is whole again, ported to the 1.19.2 API: the hand-driven terrain patch uses `WorldPresets.createNormalWorldFromPreset(...).overworld()` + `RandomState.create(settings, Registry.NOISE_REGISTRY, seed)` (`createBiomes/fillFromNoise/buildSurface/applyCarvers` all take the `RandomState`; carvers use `region.getBiomeManager()`); `NoStructures` now extends `net.minecraft.world.level.StructureManager` (null `StructureCheck`, so `checkStructurePresence` is overridden too); villages use `Structure.generate(registries, generator, biomeSource, randomState, templateManager, seed, chunkPos, 0, level, pred)` with the `village_plains` entry of `Registry.STRUCTURE_REGISTRY`.
- Verified at runtime: `PeaceCandleChurchPool` reflection id `f_205752_` is still `Holder.Reference.value` (javap + tsrg), the wrapper is installed, 1003/3000 church candidate lists are swapped (33%), 60 real villages hold 11 Peace Candle of 39 churches, the church piece places a registered Peace Candle; real terrain generation puts Glowing Mushrooms underground (21 in 13 chunks, 0 exposed), which also proves the biome modifier JSON and `ObjectHolder` feature fields work. Server suite: **364 passed / 0 failed / 2 skipped**.
- Added 8 tests (suite **373/0/2**): bean sprout / lotus / ancient furnace are in every overworld biome, in their own step, with the ported rarity (2 / 10 / 400, heightmap, in_square); bean sprout placement rules; lotus snowy check; ancient furnace (the test repaints the surrounding chunks with `snowy_plains`, then restores the biome): refused in a warm biome, over air and into water, generated on stone in a cold biome, not replaced twice; Spectre uses `SpectreChunkGenerator`, height 0..256, and a generated chunk is void.
- **Bean Sprout soil (fixed 2026-10-17):** `BeanSproutBlock extends CropBlock` only survived on farmland (1.12.2: plain-type plant), so natural generation almost never placed one; it now accepts grass, dirt, coarse dirt, podzol and farmland on every branch.
- **Bug found and fixed by the heating test:** since the 1.18 biome-cell change, `AncientFurnaceTileEntity.warmSurroundings` converted a 4x4 cell on its first column, so the other 15 columns looked already warm and kept their snow and ice (only ~1/16 of columns melted). It now classifies all columns first, then writes. The same defect is on the `1.18.2` branch (not mirrored yet).
- **Client run (first boot of the 1.19.2 client, 2026-10-17):** it boots and runs the suite: 367 passed / 8 failed / 1 skipped. New `worldgen.ancient_furnace.client_sees_the_biome_change_after_heating` (via `debug/test/ClientProbe`) passes and was mutation-checked (fails with the resync call removed). Harness fixes needed for the client: `AutoTest` registers the Spectre dimension type into the fresh-world registry copy (datapack JSON is not in `RegistryAccess.builtinCopy()`), `/rtdebug test` is sent without a trailing space (1.19 `commandUnsigned` rejects it), and the registration/real-terrain worldgen tests skip in a freshly created client world (datapack biome modifiers only apply when the saved world is reopened).
- **Client suite fixed (2026-10-17):** the 8 `use_item.*` failures were harness issues, not mod bugs: the real creative player never used up items (`RTTestRunner` now clears `abilities.instabuild` for the run) and a real client player pulled the server-side position back after `standAt` (it now also teleports through the connection). Full client suite: **377 passed / 0 failed / 1 skipped**, audit 0 failures.

### Scripted playtest (2026-10-18, `SCN_MC=1.19`, dev client)

All 26 scenarios pass (`python -u scn.py all` in `prod-test/desktop/`, plus a re-run of `imbue_effects` after a script fix). The 1.19.2 UI differences are handled in `scn.py` (`MC19`): the create-world screen is the 1.16-style single page (Game Mode (266,219) x2, More World Options (586,389), World Type (586,219)) and **Done (586,389) must be clicked before Create** or the world type/seed are ignored (a default world was created); the "experimental features" prompt after Create needs Yes (265,295); the pause menu's Save and Quit is at (426,395); `/locate biome`; effect NBT is `Id: 19` (no `b`). The scripted run also found two mod bugs (both fixed): the Spectre dimension was added to a frozen dimension registry when opening an existing world (`ModDimensions.addToServer` now unfreezes/refreezes it), and a world created through the Create World screen crashed at server start because that screen builds its registries from the vanilla pack only (the dimension type is now also registered in `BuiltinRegistries`).
- **Fresh UI-created world (answered 2026-10-18):** it has everything: `/recipe give @s randomthings:evil_tear` works, 1311 recipes unlock (vanilla + our 222), and `worldgen.bean_sprout.is_registered...` passes (not skipped), so the biome modifiers apply too. The "Loaded 7 recipes" log line is only the Create World screen's own preview load. The skips in the autotest's fresh world come from its harness path (`createFreshLevel` with a built-in registry copy), not from real play. `scn.py` also had a race (a loading screen counted as the create screen); fixed with a stricter black-box check.
- **Fresh-world worldgen scenario (2026-10-18, 1.19.2 only):** `scn.py fresh_world_worldgen` creates a world through the Create World screen and runs `/rtdebug test worldgen` in it: **22 passed / 0 failed / 0 skipped**, so every registration and real-terrain check runs (the autotest's own `createFreshLevel` world skips 5 of them, which is the control). It uses a flat world because the test runner refuses others. Harness fixes found while getting it to run: `RTTestRunner` kept ticking a run started in a world that was since closed, and the stale level blocked the next world's server thread forever (`ServerChunkCache.getChunk` join) - it now stops when the server differs; the scenario waits 8 s after the arena fill because chat text typed while the client lags is lost, and retries the command once.

### Render scenes (2026-10-18, `RT_AUTOTEST_SCENES=true`)

26 scenes rendered and compared with the 1.18.2 reference images (file sizes within 2% for 20 scenes; blocks, armor/dyes, blazing fire, rain with/without shield, rune, fluid display, light redirector, magic hood, radar, entities all look equal; the creative-tab pages differ only by the player's hotbar contents). One real regression found and fixed: the **Spectre cubes rendered with the overworld's night sky and normal lightmap** (dark gray instead of the teal fog). `ClientSetup` put `SpectreRenderInfo` into vanilla's static `DimensionSpecialEffects.EFFECTS` map by reflection, but Forge 43 resolves `forType` through `DimensionSpecialEffectsManager`; it is now registered with `RegisterDimensionSpecialEffectsEvent` (verified: `level.effects()` was `OverworldEffects` before, the teal fog is back).
