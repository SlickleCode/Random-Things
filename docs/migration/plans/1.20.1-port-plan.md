# 1.20.1 port plan (Forge 47.4.28)

Started 2026-10-18. Source: branch `1.19.2` (`c0962ea`). Branch/folder: `1.20.1`. Background: `versions/mc-1.20.md`.

## Milestones

1. **M0 Toolchain** - build.gradle/wrapper/mods.toml/pack.mcmeta bumped; project resolves and decompiles; first javac phase lists the errors.
2. **M1 Mechanical API moves** - expected: `GuiGraphics` replaces `PoseStack` GUI drawing (screens, renderers), `CreativeModeTab` registry/builder, `Registries`/`RegisterEvent` tweaks, `Item.Properties`, `ItemStack` NBT helpers, recipe/`RecipeSerializer` changes, `BlockEntityRenderer` and `ItemInHandRenderer` signatures, `DamageSource`/`DamageTypes` registry (1.19.4), `Level#getBlockState`-style renames, `ForgeRegistries` vs `Registries`, `PlayerChatMessage`.
3. **M2 Worldgen** - 1.19.3/1.19.4/1.20 structure and feature API moves; Spectre generator and dimension; Peace Candle church pool swap (re-check reflection ids); Ancient Furnace resync.
4. **M3 Chat** - 1.19.3+ signed chat changes.
5. **M4 Rendering / client** - `GuiGraphics`, `Matrix4f`/`Quaternionf` (JOML) instead of `Vector3f`/`Quaternion`, `RenderType`/`VertexConsumer` changes, `ItemDisplayContext`, creative tabs.
6. **M5 Coremods** - re-read the 15 transformers' anchors in the 1.20.1 bytecode (Mojang + SRG ids); `docs/migration/tools/CoremodCheck.java`.
7. **M6 Boot + suites** - server suite, client suite, resource audit, GUI click test, render scenes, scripted playtest, production (SRG) jar check in `prod-test/1.20.1`.

## Status

### M0 + M1 + server boot (2026-10-18)

**`./gradlew compileJava` is green and the dedicated server suite gives 375 passed / 0 failed / 3 skipped (of 378)** - the same result as 1.19.2. The first javac phase listed 1124 errors; the conversion scripts are in `docs/migration/tools/` (`errfix_1201.py` position-exact fixer fed by a javac log, `m1_1201_material.py`, `m1_1201_gui.py`, `m1_1201_bulk.py`, `m1b_1201.py`; `errsum.py`/`errfiles.py`/`errlist.py` summarise a log).

What changed (checked with `javap` on the 1.20.1 mapped jar):

- **Toolchain:** ForgeGradle `[6.0.24,6.2)`, Gradle 8.8, `jar.finalizedBy('reobfJar')`, Forge 1.20.1-47.4.28, `pack_format` 15, `loaderVersion [47,)`.
- **Materials are gone:** `Block.Properties.of(Material.X[, MaterialColor.Y])` became `of().mapColor(MapColor.Y)` plus the matching `instrument(...)`/`pushReaction(...)`/`ignitedByLava()` (table in `m1_1201_material.py`); `getMaterial().isReplaceable()` -> `canBeReplaced()`, `isLiquid()` -> non-empty fluid state.
- **Creative tab:** `.tab(RT_ITEM_GROUP)` removed from every `Item.Properties`; the tab is built with `CreativeModeTab.builder()` and registered on `Registries.CREATIVE_MODE_TAB` in `RegisterEvent`; its contents are every Random Things item in registry order (`DiaphanousBlockItem.addCreativeStacks` adds its stone/inverted stacks).
- **GUI:** `GuiGraphics` instead of `PoseStack` in all screens/widgets/toast (`font.draw` -> `graphics.drawString`, `blit` with the bound texture, `GuiComponent.fill` -> `graphics.fill`, `new Button(...)` -> `Button.builder(...).bounds(...).build()`); `AbstractWidget.x/y` -> `getX()/getY()`; custom buttons pass `DEFAULT_NARRATION`; `TooltipButton.getTooltip` was renamed `getTooltipText` (clashes with `AbstractWidget.getTooltip`); the old per-widget `renderToolTip` loops (no tooltip text on those screens) were dropped.
- **Entity/level:** `Entity.level` is a method; `getAddEntityPacket` returns `Packet<ClientGamePacketListener>`; `positionRider(Entity, MoveFunction)`; `new BlockPos(double...)` -> `BlockPos.containing`; `ServerPlayer.getLevel()` -> `serverLevel()`.
- **Damage sources:** `EntityDamageSource`/`IndirectEntityDamageSource` are gone: "direct hit by an entity" is `getEntity() != null && getDirectEntity() == getEntity()`; Spectre spirit checks use `DamageTypes.*`; thrown eggs use `damageSources().thrown(...)`.
- **Registries:** `Registry.X_REGISTRY` -> `Registries.X`; capabilities moved to `ForgeCapabilities`; `ForgeMod.REACH_DISTANCE` -> `BLOCK_REACH`; `CommandSourceStack.sendSuccess` takes a supplier; `LocalPlayer.commandUnsigned` -> `connection.sendUnsignedCommand`.
- **Worldgen is data now:** no `BuiltinRegistries` in 1.20. `data/randomthings/worldgen/{configured,placed}_feature/*.json` (rarity 2/10/400/4 + in_square + heightmap + biome) replace `ModFeatures.registerConfiguredFeatures`; `data/randomthings/dimension/spectre.json` replaces the code-registered dimension and the 1.19.2 `addToServer`/`unfreeze` workaround (a UI-created world loads the mod pack in 1.20); only the chunk generator codec (`BuiltInRegistries.CHUNK_GENERATOR`) is registered from code. `SpectreChunkGenerator` extends `ChunkGenerator(BiomeSource)` with a `mapCodec(...).codec()`.
- **Biomes:** `ForgeRegistries.BIOMES` is empty in 1.20.1 (data-pack registry). `BiomeUtil.byId/ids/id` read the current world's registry; every `ForgeRegistries.BIOMES` use was switched (this was the one real runtime bug in the first server run: Biome Crystal/Radar).
- **Recipes:** `CustomRecipe(id, CraftingBookCategory)`, `SimpleCraftingRecipeSerializer`, `assemble(container, RegistryAccess)`, `getResultItem(RegistryAccess)`; `TransientCraftingContainer`.
- **Coremods:** `getSignal`/`getDirectSignal` moved into the `SignalGetter` interface, so `WorldRedstonePowerTransformer`/`WorldReaderStrongPowerTransformer` now target `net.minecraft.world.level.SignalGetter` (`AsmHandler.overrideRedstonePower/overrideStrongPower` take a `SignalGetter`). The other transformers still have to be re-verified (CoremodCheck + client run + production).
- **Chat:** Forge 47 has no signed-chat event: `ServerChatEvent(player, rawText, Component)` like before (`getRawText()`/`getMessage()`).
- Armor: `ArmorMaterial.getDurabilityForType/getDefenseForType`, `ArmorItem.Type`. Items: `onUseTick(Level, entity, stack, count)`. `LootParams.Builder` in `Block.getDrops`. `StandingAndWallBlockItem(..., Direction.DOWN)`.

### Client, GUI, render scenes, production (2026-10-18)

- **Dev client suite 377 passed / 0 failed / 1 skipped, audit 0 failures / 0 warnings** (147 blocks, 241 items, 222 recipes). The worldgen registration tests run (do not skip) in the autotest's fresh world, because the features/biome modifiers are datapack JSON now. First boot needed `run/options.txt` with `onboardAccessibility:false` (1.20's first-run accessibility screen blocks the autotest on the title screen).
- **GUI click-through:** 28 GUIs, 37 clicks, 0 failures (same as 1.19.2). **Render scenes:** 26 scenes, sizes within ~2% of the 1.18.2 references except the creative-tab pages (`items_*`, the 1.20 creative screen differs); armor, Magic Hood, Light Redirector, blazing fire, rain, Spectre fog checked by eye.
- **Coremods:** `docs/migration/tools/CoremodCheck.java` now lists the changed methods per transformer; all 14 report their intended methods on 1.20.1 (it needs asm 9.6 + asm-tree/commons/analysis/util + nashorn-core 15.4 on the classpath). Two real breaks found this way / by the production run: `ItemRendererTransformer` still matched `ItemTransforms$TransformType` (now `ItemDisplayContext`, so its `render` hook had silently not applied), and `BlockRendererDispatcherTransformer` lost the trailing boolean of the Forge `renderBatched` overload. `docs/migration/tools/srgcheck.py` checks every SRG id in the transformers/reflection against the production jars: `getSignal`/`getDirectSignal` are `m_277185_`/`m_277075_` on `SignalGetter` in 1.20.1 (the old ids were missing, which made `coremod.redstone_interface...` fail only in the production run).
- **Production (SRG) check, `prod-test/1.20.1`** (Forge 1.20.1-47.4.28 installer for server and client + `fetch-libs.py`; the server starts with `java @user_jvm_args.txt @libraries/net/minecraftforge/forge/1.20.1-47.4.28/win_args.txt nogui`): server suite **375 / 0 / 3**, client suite **377 / 0 / 1**, audit 0 failures.

### Scripted playtest (2026-10-18, `SCN_MC=1.20`, dev client)

All 26 scenarios pass (`python -u scn.py all`, plus a re-run of `sound_dampener` and `worn_armor`). `scn.py` handles 1.20.1 with `MC20`: the create-world screen is tabbed (Game / World / More): name field (426,117), Game Mode clicked twice = Creative with cheats, World tab (428,27), seed field (426,173), World Type button (266,89), Create (266,443); with no saved world Singleplayer opens that screen directly after "Preparing for world creation...". `desk.py click` now nudges the cursor 3 px first (GLFW ignores a click when the cursor already rests on the target, which made every click after a restart a no-op). Real findings: `ArmorLayerTransformer` still matched the 1.19.2 `renderModel` descriptor (1.20.1: `(PoseStack, MultiBufferSource, int, ArmorItem, Model, boolean, float, float, float, ResourceLocation)V`), so dyed armor drew white until fixed (the offline `CoremodCheck` could not see this because the transformer still changed `renderArmorPiece` through another edit); the `sound_dampener` failure was a muted master volume in `run/options.txt` (the mod deliberately ignores muted sound categories), not a bug.
