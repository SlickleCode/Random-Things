# P2 parity report (baseline 1.14.4 vs 1.16.5, 1.18.2, 1.19.2, 1.20.1, 1.20.6, 1.21.1, 1.21.4, 1.21.11)

Method: all nine branches extracted with `git archive` (src + docs); every class of the assigned pages diffed branch-to-branch (imports, comments and
annotations stripped) and every non-API hunk read; the behaviour hooks (spawn coremod, Super Lubricent event handlers, hoe/shovel events, loot
handler, worldgen registration, biome modifiers, loot tables, tags, structure NBT) read on all nine branches. No vanilla/Forge jar is available, so
statements about vanilla API behaviour are from knowledge and marked SUSPECTED. CONFIRMED = both sides of the code read.
Paths below are relative to `src/main/java/lumien/randomthings/`.

## Differences found (12)

### D1 Fertilized Dirt: which plants get the 3 extra growth ticks (CONFIRMED code, SUSPECTED effect)
- 1.14.4 `block/FertilizedDirtBlock.java:52`, 1.16.5..1.20.6 (`:58` on 1.20.6): `aboveBlock instanceof IPlantable && aboveState.ticksRandomly()`.
- 1.21.1/1.21.4/1.21.11 `:57`: `aboveBlock instanceof net.minecraft.world.level.block.BushBlock && isRandomlyTicking()` (IPlantable no longer exists).
- Forge patches `SugarCaneBlock` and `CactusBlock` (not BushBlock subclasses) to implement IPlantable, and `canSustainPlant` still lets both stand on untilled
  Fertilized Dirt on every branch, so on <=1.20.6 they get the boost and on 1.21.1+ they do not. Wiki fact: "gives the plant above it up to 3 extra growth ticks".
- Related, same file: ground rules (`canSustainPlant`) were rewritten from `PlantType` switch to `TriState`/instanceof on 1.21.1+; I mapped each case
  (Desert/Beach -> untilled, Crop -> tilled, Plains/Cave -> untilled or beetroots, Nether/Water -> never, attached stem -> always) and found them equivalent.

### D2 Fertilized Dirt: hoe tilling goes through a different path (SUSPECTED)
- 1.14.4 `RandomThings.java:112-123`, 1.16.5 `:114`, 1.18.2 `:129`: `UseHoeEvent`, handler sets `TILLED`, plays `ITEM_HOE_TILL`, `Result.ALLOW`
  (Forge returns SUCCESS right after the hook, before vanilla checks).
- 1.19.2 `:127`, 1.20.1 `:125`, 1.20.6/1.21.1 `:130`, 1.21.4/1.21.11 `:131`: `BlockToolModificationEvent`(HOE_TILL) `setFinalState(...)`, vanilla `HoeItem` finishes the job.
- Expected consequence: the hoe loses no durability on 1.14.4/1.16.5/1.18.2 but loses 1 on 1.19.2+; the 1.14.4 path also tills when something is above the
  block or when clicked from below (vanilla's "air above / not DOWN" check runs after the hook on old versions). Wiki says only "use a hoe on it".

### D3 Config `features.MagneticEnchantment` stops gating the enchantment on 1.21.1+ (CONFIRMED)
- 1.14.4 `enchantment/MagneticEnchantment.java:35` (`canApplyAtEnchantingTable`) and `:40` (`isAllowedOnBooks`) return false when the option is false, plus
  `handler/MagneticLootModifier.java:41`; same on 1.16.5, 1.18.2, 1.19.2, 1.20.1, 1.20.6.
- 1.21.1/1.21.4/1.21.11: class `MagneticEnchantment` is gone, enchantment is `data/randomthings/enchantment/magnetic.json` and is added to the vanilla tags
  `in_enchanting_table`, `tradeable`, `on_random_loot`; the option is only read in `MagneticLootModifier.java:39` (disables the effect). With the option
  off the enchantment is still offered at tables/trades/loot and just does nothing. The configuration page says "obtainable ... and works".
- Also: 1.14.4-1.20.1 apply to `EnchantmentType.DIGGER` (pickaxe/axe/shovel/hoe), 1.20.6+ to `#minecraft:enchantable/mining` (SUSPECTED: also shears).

### D4 Block of Sticks: four overrides are dead code from 1.16.5 on (CONFIRMED structure, SUSPECTED effect)
- `block/SticksBlock.java` 1.14.4 `:63-90`: `func_220080_a` (AO), `propagatesSkylightDown`, `causesSuffocation`, `isNormalCube`, `canEntitySpawn` (none has `@Override`).
  These are the 1.14 `Block` methods. 1.16.5 (`:57-80`), 1.18.2 (`:50-73`) ... 1.21.11 keep the very same methods, but from 1.16 vanilla moved them to
  `Block.Properties` (`setSuffocates`, `setAllowsSpawn`, `setOpaque`/redstone conductor); the glass blocks were migrated (`LapisGlassBlock`, `QuartzGlassBlock`,
  `TriggerGlassBlock` use `.setSuffocates/.isSuffocating`), the sticks block was not. `func_220080_a` also has no counterpart on 1.18.2+ (`getShadeBrightness`).
- Expected effect on 1.16.5-1.21.11 only: a player/mob whose head is inside a Block of Sticks takes suffocation damage, hostile mobs can spawn on it,
  it conducts redstone (strong power) - none of that on 1.14.4. Not in the wiki text (it only has lifetime/return range), so low priority.

### D5 Super Lubricent: server-side boat cap skips chest boats on 1.19.2-1.21.1 (CONFIRMED)
- `RandomThings.java` 1.19.2 `:320`, 1.20.1 `:318`, 1.20.6 `:325`, 1.21.1 `:325`: `getEntities(EntityType.BOAT, ...)`; chest boats (EntityType.CHEST_BOAT, new in 1.19)
  are never capped on the server, while `SuperLubricentPhysics.slipperinessFor` (instanceof `Boat`, includes ChestBoat) gives them zero friction and the client sweep
  (`client/ClientSetup.java`, `instanceof Boat`) caps them -> uncapped server speed / turn rate, client/server mismatch.
- 1.14.4-1.18.2 have no chest boats; 1.21.4 `:326` and 1.21.11 use `EntityTypeTest.forClass(AbstractBoat.class)` and are correct.
- Wiki fact affected: "Boats on them are capped at 0.35 blocks per tick and turn at most 15 degrees per tick".

### D6 Ancient Furnace: converted biome list differs between <=1.16.5 and >=1.18.2 (CONFIRMED)
- 1.14.4 `tileentity/AncientFurnaceTileEntity.java:102-114` and 1.16.5 `:108-120` (13 entries): taiga, frozen ocean, frozen river, snowy tundra, snowy mountains,
  taiga hills, snowy beach, snowy taiga (+hills, +mountains), giant tree taiga hills, taiga mountains, ice spikes.
- 1.18.2 `:109` .. 1.21.11 (12 entries, identical on all >=1.18.2): taiga->forest, frozen ocean->ocean, **deep frozen ocean->deep ocean (new)**, frozen river, snowy plains->plains,
  **snowy slopes->meadow (new)**, **grove->forest (new)**, snowy beach, snowy taiga->birch forest, old growth pine/spruce taiga->old growth birch forest, ice spikes->flower forest.
  Old hill/mountain variants no longer exist; 1.14.4/1.16.5 never converted Deep Frozen Ocean although it existed. The wiki list ("taiga, snowy tundra, ice spikes, frozen
  oceans and rivers") fits both, but the exact set is not the same.
- Also (SUSPECTED, trivial): final explosion 1.14.4 `:148` `Explosion.Mode.BREAK` (all drops) vs 1.20.1+ `:155` `ExplosionInteraction.BLOCK` (drop-decay game rule applies).

### D7 Lotus: "Snowy" biome set and seed ground are data/library-defined, not identical (SUSPECTED)
- `worldgen/LotusFeature.java:45` (1.14.4/1.16.5/1.18.2: Forge `BiomeDictionary.Type.SNOWY`) vs `:51` (1.19.2+: `BiomeUtil.hasType(biome,"SNOWY")` = biome tag `forge:is_snowy`
  on 1.19.2/1.20.1, `c:is_snowy` on 1.20.6+). The membership of those lists (frozen peaks, jagged peaks, grove, snowy slopes, deep frozen ocean, frozen river ...) is decided by
  Forge/NeoForge data, so Lotus can generate in a different set of biomes. Only snowy_plains is covered by the WorldgenTests.
- `item/LotusSeedsItem.java:38` (1.14.4..1.20.6: `canSustainPlant(..., this)` with `PlantType.Plains` = grass/dirt/coarse dirt/podzol/farmland, and untilled Fertilized Dirt) vs
  `:36` (1.21.1+: `canSustainLotus` = block extension, else `BlockTags.DIRT` or farmland, which adds mycelium, moss, mud, rooted dirt ...). `LotusBlock.mayPlaceOn` is
  grass/dirt/farmland everywhere, so on those extra grounds the seed is placed and the plant pops off again (seed lost).
- Wiki discrepancy on ALL branches (not parity): page says seeds "can only be planted on farmland"; code accepts grass/dirt/farmland (and more, see above).

### D8 Heights: world limits differ by design from 1.18.2 (CONFIRMED, informational)
- Glowing mushroom `block/GlowingMushroomBlock.java:117,128`: 1.14.4/1.16.5 `y<0 || y>=256` cannot stay; 1.18.2+ uses `getMinBuildHeight()/getMaxBuildHeight()` (-64..320), so mushrooms
  may survive/spread below y=0. Worldgen itself still clamps to `max(0,minY)` (`worldgen/GlowingMushroomFeature.java`), Ancient Furnace/Bean Sprout/Lotus clamp to real build height.
  Deepslate is not in `canSustainBush` (grass/dirt/stone/fertilized dirt/mycelium), so deep caves get none. Matches the cave layout change, but the wiki "caves, below the surface" is only true for y>=0.

### D9 Material-derived tool requirement of stone-like blocks (SUSPECTED)
- 1.14.4/1.16.5 use `Material.ROCK` (Ancient Furnace `block/AncientFurnaceBlock.java:42`, Stained Bricks `StainedBrickBlock.java:15`, Super Lubricent Stone
  `SuperLubricentStoneBlock.java:27`, also Platform/Light Redirector use WOOD). In those versions ROCK requires a pickaxe (otherwise no drop).
  1.18.2+ (`Material.STONE`, later no Material) and no `requiresCorrectToolForDrops()` anywhere (grep) -> they drop with bare hands. No `mineable/pickaxe` tag either.

### D10 Worldgen biome filter changes with each generation of the registration (CONFIRMED, informational)
- 1.14.4 `RandomThings.java:699-702`: `ForgeRegistries.BIOMES.forEach(...)` - every biome incl. Nether/End/void (features self-gate and are inert there).
- 1.16.5 `worldgen/ModFeatures.java:85`, 1.18.2 `:86`: `BiomeLoadingEvent`, skips categories NETHER/THEEND/NONE (so any modded non-vanilla-category biome still gets them).
- 1.19.2..1.21.11: `data/randomthings/forge|neoforge/biome_modifier/*.json` with `#minecraft:is_overworld`; placed features: 1.19.2 in code (`ModFeatures.java:69-83`), 1.20.1+ as JSON.
  Placement is the same everywhere: 1/N chunks (bean sprout 2, lotus 10, ancient furnace 400, glowing mushroom 4) -> random column -> MOTION_BLOCKING heightmap; steps identical.

### D11 Peace Candle support check, Diaphanous recipe target check (CONFIRMED code, equivalent by intent)
- `block/PeaceCandleBlock.java` 1.14.4/1.16.5 `getBlockState(pos.down()).isSolid()`, 1.18.2+ `.canOcclude()` (1.16 `isSolid` was renamed `canOcclude`; on 1.14.4 render layer decides). Treated as same.
- `recipes/DiaphanousSetRecipe.java:47` 1.14.4/1.16.5 `!block.hasTileEntity(defaultState)` vs 1.18.2+ `!(block instanceof EntityBlock)`: same for vanilla blocks.

### D12 `randomTick` delegation (CONFIRMED present on 1.20.6+, SUSPECTED fine before)
- Colored Grass, Fertilized Dirt, Glowing Mushroom, Lotus use `tick()` for random ticks. 1.20.6+ add an explicit `randomTick -> tick` override (comment in `LotusBlock`: "1.20.5 made randomTick a no-op").
  1.14.4-1.20.1 rely on the vanilla default delegating to `tick`, which was true then. No action unless a test fails.
