# P4 parity report (baseline 1.14.4 vs 1.16.5, 1.18.2, 1.19.2, 1.20.1, 1.20.6, 1.21.1, 1.21.4, 1.21.11)

Method: every implementing class was extracted with `git show origin/<branch>:<path>` and diffed in a chain (1.14.4 -> 1.16.5 -> ... -> 1.21.11) with imports and whitespace ignored. I read the full 1.14.4 class and every diff hunk, ignoring pure API renames. "Full" below means full class plus all diff hunks. The file:line citations are approximate (line numbers are of the raw class files).

Classes read in full: EclipsedClockItem/Entity, TimeInABottleItem, TimeAcceleratorEntity, WeatherEggItem, ThrownWeatherEggEntity, WeatherCloudEntity, GoldenEggItem, ThrownGoldenEggEntity, GoldenChickenEntity, PodBlock, SummoningPendulumItem, LootHandler, StableEnderpearlItem, EvilTearItem, ArtificialEndPortalEntity, FlooNetworkHandler, FlooFireplace(Entity), FlooBrick(Block/TileEntity), FlooSignItem, FlooPouchItem, FlooTokenItem, PortkeyItem, PortkeyCamoRecipe, EnderBridgeBlockBase/EnderBridgeBlock/Prismarine*, EnderBridgeTileEntity (+Prismarine), EnderAnchorTileEntity/Block, AnchorChunkLoader, EnderBucketItem, ReinforcedEnderBucketItem, EnderLetterItem/Container/Handler, EnderMailboxBlock/TileEntity/Container, SoundBoxBlock/TileEntity, SoundDampenerBlock/TileEntity/Containers, PortableSoundDampenerItem, SoundPatternItem, SoundRecorderItem/Container, PlayedSoundMessage, ItemInventoryHandler, BeanItem, BeanStewItem, BeanSproutBlock, BeanStalkBlock, BeanSproutFeature, ModFeatures, ImbueEffect, ModEffects, ImbueItem, ImbuingStationTileEntity, ImbuingRecipe(+Handler), the hard-coded imbuing recipes in RandomThings.java, the imbue event listeners, the Floo chat handler, the Portkey pickup listener, the dropped-item tick listeners, ClientSetup.onPlaySound, ModEntityTypes (entity sizes), and the bean_pod / bean_sprout loot tables (identical JSON on all 9 branches).

Number of differences found: 8 real/probable parity differences (list A) plus 4 lower-confidence items (list B). Everything else: no difference found.

## A. Differences (behaviour)

### A1. Weather Egg: cloud ceiling differs, so the time-to-change-weather differs (CONFIRMED)
- Affects wiki fact: "slowly goes upwards, once it reaches the sky it changes the weather".
- 1.14.4 `entity/WeatherCloudEntity.java` tick(): `this.posY < this.world.getHeight()` (256). 1.16.5: `getPosY() < world.getHeight()` (256).
- 1.18.2 to 1.21.1: `this.getY() < this.level.getMaxBuildHeight()` (320 in the Overworld). 1.21.4/1.21.11: `getMaxY() + 1` (320).
- Effect: in the Overworld the cloud climbs to Y=320 on 1.18.2+ but only to Y=256 on 1.14.4/1.16.5. Climb speed is roughly 0.007 blocks/tick for 200 ticks, then it accelerates, so the weather change happens noticeably later on 1.18.2+. The Nether and End cap at 256 on every version. The weather duration (300..899 s) is the same on all branches.

### A2. Bean stalk growth limit (CONFIRMED)
- Affects wiki fact: "continue to grow till it hits a block / the height limit"; the magic bean ends in a Bean Pod.
- 1.14.4 and 1.16.5 `block/BeanStalkBlock.java` tick(): stops at `up.getY() >= 255`, and the Magic Bean puts the pod at `up.getY() >= 253`.
- 1.18.2 to 1.21.1: `getMaxBuildHeight() - 1` and `- 3` (pod at Y=317 in the Overworld). 1.21.4/1.21.11: `getMaxY() + 1 - 1` and `- 3`, same numbers.
- Effect: the stalk and pod sit at Y=253 on 1.14.4/1.16.5 but at Y=317 on 1.18.2+ (Overworld). The Nether is 253 on all versions. The same change is in `worldgen/BeanSproutFeature.java`: the Y range goes from `0 < y < 255` to `minBuildHeight < y < maxBuildHeight - 1`.

### A3. Portkey landing-spot search (CONFIRMED)
- Affects wiki fact: "within 2 blocks of the target, on a solid block with room to stand, up to 10 blocks below the target height".
- Listener in `RandomThings.java` ("Teleports whoever picks up a primed, bound PortkeyItem"):
  - Lower bound: 1.14.4/1.16.5 `y >= 0`; 1.18.2+ `y >= level.getMinBuildHeight()` (1.21.4+: `getMinY()`). Below Y=0 the search area is wider on 1.18.2+, so a target at Y<10 gets extra candidate spots there.
  - "Solid" test: 1.14.4 `Block.hasSolidSide(state, world, pos, UP)` (full top face); 1.16.5 `Block.hasEnoughSolidSide(world, pos, UP)`; 1.18.2+ `Block.canSupportCenter(level, pos, UP)`. These three differ for partial blocks (bottom slabs, fences, glass panes, etc.), so the pool of accepted spots differs.
- The prime time is the same on all branches (`dropCounter > 100`, i.e. 5 s).
- The dimension is stored as an int id on 1.14.4 and as a registry-key string on 1.16.5+. This is not a behaviour difference, but old 1.14.4 portkeys are not readable on 1.16.5+.

### A4. Artificial End Portal: arrival position in the End (SUSPECTED, 1.21.1 / 1.21.4 / 1.21.11)
- `entity/ArtificialEndPortalEntity.java` playerTouch():
  - 1.14.4: `entityIn.changeDimension(DimensionType.THE_END)`. 1.16.5 to 1.20.6: `changeDimension(server.getLevel(END))`. Both use vanilla's End entry logic (obsidian platform at 100,50,0).
  - 1.21.1: `changeDimension(new DimensionTransition(endLevel, entityIn, DO_NOTHING))`.
  - 1.21.4: `entityIn.teleport(new TeleportTransition(endLevel, entityIn, DO_NOTHING))`.
  - 1.21.11: `teleport(new TeleportTransition(endLevel, entityIn.position(), entityIn.getDeltaMovement(), yRot, xRot, DO_NOTHING))`.
- I believe the (level, entity, post) constructors on 1.21.1/1.21.4 use the level's shared spawn, and the 1.21.11 variant keeps the player's current coordinates. In both cases the End obsidian platform is not created. Neither is the vanilla End-portal entry. I could not read the Minecraft jar, so this needs an in-game check.
- Charge time (200 ticks, 10 s), structure re-check every 40 ticks, the structure shape and the config gate are identical on all branches.

### A5. Bean Sprout natural generation: biome set (CONFIRMED, low impact)
- 1.14.4 `RandomThings.registerWorldgenFeatures`: added to every biome, including Nether/End, with `CHANCE_HEIGHTMAP 2`.
- 1.16.5/1.18.2 `ModFeatures.onBiomeLoading`: skips NETHER, THEEND and NONE categories.
- 1.19.2 to 1.21.11: biome modifier `"biomes": "#minecraft:is_overworld"`.
- The placement is the same everywhere (1 in 2 chunks, a random column, MOTION_BLOCKING). The sprout can only exist on grass/dirt-type blocks, so the effect on a real world is tiny.

### A6. Imbue on-hit filter (CONFIRMED, edge case)
- `RandomThings.java` LivingHurtEvent listener:
  - 1.14.4 to 1.19.2: `source instanceof EntityDamageSource && !(source instanceof IndirectEntityDamageSource)`.
  - 1.20.1 to 1.21.11: `source.getEntity() != null && source.getDirectEntity() == source.getEntity()`.
- Melee hits are identical (fire 10 s, Wither II 5 s, Poison II 10 s, XP doubled via LivingExperienceDrop). They differ for explosions caused by a player with an imbue (for example TNT the player lit): old branches count them as a hit and new ones do not.
- The effect duration (24000 ticks, 20 min), the imbue-clears-previous logic and the hard-coded imbuing station recipes (4 imbues + the vine/bone meal/cobblestone water-bottle recipe, 200-tick brew) are identical on all 9 branches. The water bottle is `PotionHelper.potion(WATER)` on 1.20.6+ (components) instead of NBT; ingredient comparison is `isSameItemSameComponents`, which is equivalent.

### A7. Golden Chicken ingredient set depends on the loader's gold-ore tag (SUSPECTED)
- `GoldenChickenEntity.livingTick/aiStep`: uses `Tags.Items.ORES_GOLD` on every branch (1.14.4/1.16.5: `contains(item)`, later `stack.is(tag)`).
- The tag contents are defined by Forge/NeoForge, not by the repo, so they can differ per version (deepslate gold ore from 1.18, nether gold ore in some versions). I could not read the loader jars. Lay timer (600..1199 ticks), yield (3 ingots), health 4 and speed 0.25 are identical.

### A8. Block mining speed with a pickaxe (SUSPECTED, cross-cutting)
- 1.14.4/1.16.5 blocks use `Material.ROCK` (pickaxe breaks them faster through the material check). From 1.18.2 on, speed comes from the `mineable/pickaxe` tag, and the repo only ships `mineable/axe.json` and `mineable/shovel.json` (no `pickaxe.json` on any branch).
- Affected blocks on my pages: Floo Brick, Ender Bridge, Prismarine Ender Bridge, Ender Anchor, Ender Mailbox, Sound Dampener. No block needs a correct tool for drops, so drops are the same; only the break time with a pickaxe differs.

## B. Lower-confidence / minor notes
- B1. Ender Bucket (`EnderBucketItem`, `ReinforcedEnderBucketItem`): from 1.20.6 on `isFluidBlock` is only `block instanceof BucketPickup`; `IFluidBlock` support (modded fluid blocks) was dropped. Vanilla water/lava behave the same: the flood-fill limit of 2000 blocks, direction order, capacity 1000 / 10000 mB, shift = collect all, and placing are identical on all branches. 1.21.11 reads the fluid from the `FLUID` data component directly instead of the capability (equivalent).
- B2. Ender Mailbox player lookup: 1.14.4 to 1.21.4 use `getPlayerProfileCache()/getProfileCache().get(name)`. 1.21.11 uses `services().nameToIdCache().get(name)`. Whether this still looks up unknown (never-joined) names online, as the older caches did, could not be verified without the jar.
- B3. Portkey no-despawn: 1.14.4 `setNoDespawn()` and 1.18.2+ `setExtendedLifetime()` both set age to -32768. The primed portkey therefore still despawns after about 32 minutes on every branch (the wiki says "won't despawn anymore").
- B4. Time in a Bottle accrual "in any inventory slot": the code relies on `inventoryTick`. On 1.21.11 the signature changed to `(stack, ServerLevel, entity, EquipmentSlot)` and the armor/offhand slots may no longer tick items the way they did on <= 1.21.4. I did not verify this.

## C. No difference found (full class read)
- Eclipsed Clock (item, entity, +100 ticks per server tick, 600 ticks per click, 110-tick cooldown, cost = distance to target, walls only): same on all branches. The 1.21.1+ hit box (0.75 x 0.75) equals the old 12 x 12 pixel box.
- Time in a Bottle / Time Accelerator entity: caps (622080000), 30 s base, doubling 2x to 32x, costs, pitches, 1/1365 random-tick chance: same. The tile entity is ticked through `getTicker` on 1.18+ (equivalent).
- Weather Egg item / thrown egg / dispenser behaviour, 5 to 15 minute duration: same except A1.
- Golden Egg item / thrown egg / Pod Block golden-egg drop (config gate, explosion chance `1/radius`): same. The `bean_pod` and `bean_sprout` loot tables are byte-identical in content on all 9 branches (bean pod: iron 8-20, gold 4-15, diamond 1-5, emerald 0-2, beans 4-8).
- Summoning Pendulum: capacity 5, FIFO release, monster/player exclusion, loot chances (10% simple dungeon, 50% stronghold corridor via `LootHandler`, same config gate): same. Rarity RARE moved from `getRarity` to item properties on 1.20.6+ (equivalent).
- Stable Ender Pearl: 140-tick countdown, 10-block radius, bind on right click, bound-player teleport, tick driver in `RandomThings.java`: same.
- Floo: network handler, Levenshtein destination matching, same-dimension storage, sign (20 brick limit), pouch (128), token (age > 100 + on ground, 5-block fireplace check), fireplace entity (260 ticks), chat handler, break logic: same. (Floo network data is stored per dimension on every branch.)
- Ender Bridge / Prismarine / Anchor: scan start at offset 2, 1 vs 10 steps per tick, loaded-chunk check, +-2 teleport box, anchor chunk forcing + config: same.
- Ender Letter / Mailbox / Container: 9 slots, 200 characters, receiver field 64, ownership, 10 s glow refresh (200 ticks), inbox of 9: same. Letters and the mailbox inbox are stored in `EnderLetterHandler.get(level)`, i.e. per dimension, on every branch.
- Sound Box (once per rising edge, any-hand pop-out, drop on break), Sound Dampener (20 block radius, 9 slots, recorded patterns only), Portable Dampener (36 main slots only), Sound Pattern (sneak clear), Sound Recorder (10 unique sounds, sneak to start/stop, records from any of 36 slots, ignores music/records and sounds muted by a placed dampener): same. 1.21.4+ move the item-model predicates to JSON (render only).
- Bean item/stew/sprout (right click on max age gives 1-2 beans), stalk speeds (0.2 / 0.5 blocks, 5 / 1 tick growth), stew (8 hunger, 0.6 saturation, bowl returned): same apart from A2/A5.
- Entity types (sizes, tracking range, update interval) for all my entities: identical.

## D. Wiki-versus-code notes (the same on all 9 branches, so not parity bugs)
- No `Nature Core` / plant chest code exists on any branch (the wiki Bean page mentions it).
- Golden Chickens can be bred with seeds in code (`isBreedingItem` seeds), while the wiki says they cannot.
- Ender Letters/Mailboxes: wiki says "work across dimensions", but the saved data is per dimension on every branch (`getDataStorage()` of the mailbox's own level). Please verify in game. The same applies to Floo networks (wiki says same dimension, consistent).
