# P3 parity report (baseline 1.14.4 vs 1.16.5, 1.18.2, 1.19.2, 1.20.1, 1.20.6, 1.21.1, 1.21.4, 1.21.11)

Pages: spectre_anchor, spectre_charger, spectre_coils, spectre_key (dimension, teleporter, cube), spectre_lens, spectre_sapling, spectre_tools,
spectre_illuminator, ectoplasm, divining_rods, emerald_compass, golden_compass, position_filter, entity_filter, id_card, chunk_analyzer, magic_hood,
magnetic_enchantment, blaze_and_steel, escape_rope, bottle_of_air, runic_dust, luminous_powder.

Method: extracted every implementing class from every branch (git show origin/<b>:path) and diffed them as a chain (1.14.4->1.16.5->1.18.2->1.19.2->1.20.1->1.20.6->1.21.1->1.21.4->1.21.11),
reading each diff hunk for behaviour (constants, conditions, tick rates, ranges, drops, config gating) and ignoring pure renames. Full class reads of all item/block/TE/handler/entity classes
listed below; client renderers (DiviningRodRenderer, SpectreRenderInfo, RTItemModels) only grep-checked for constants (160 ticks, 60 per tick, +-5 cube, hand order are identical on all branches).
Also read: AsmHandler hooks + coremods.json / transformer lists per branch, RandomThings.java event blocks (Clone, LivingDeath, LivingUpdate, hood events), LootHandler, loot tables for spectre blocks (identical on all branches),
dimension_type/dimension JSON, mineable/enchantment tags, ModItems registrations (stack sizes / durability / rarity identical: blaze 64, rope 20, hood RARE, stack 1 for compasses/filters/key/charger).
Not done: nothing was run. Vanilla-source claims marked SUSPECTED are from memory of vanilla code, not read from a jar.

Totals: 4 CONFIRMED differences, 10 SUSPECTED, plus 6 data-format / natural-version notes.

---------------------------------------------------------------------------------------------------

## CONFIRMED differences (both sides read)

### C1. magnetic_enchantment: "MagneticEnchantment=false" no longer makes the enchantment unobtainable on 1.21.1, 1.21.4, 1.21.11
- 1.14.4 `enchantment/MagneticEnchantment.java:33-41`: `canApplyAtEnchantingTable` and `isAllowedOnBooks` return false when `RTConfig.MAGNETIC_ENCHANTMENT` is false (table and books closed). Same code survives on 1.16.5, 1.18.2, 1.19.2, 1.20.1 and 1.20.6 (`MagneticEnchantment.java:25-30` on 1.20.6).
- 1.21.1/1.21.4/1.21.11: class `MagneticEnchantment` is gone (enchantment is `data/randomthings/enchantment/magnetic.json`); `data/minecraft/tags/enchantment/in_enchanting_table.json`, `on_random_loot.json`, `tradeable.json` list it unconditionally. The only remaining config check is `handler/MagneticLootModifier.java:39` (effect off). So with the config false the enchantment is still offered by the table / villagers / random loot, it just does nothing.
- Affects: config text "obtainable (enchanting table, books, loot) and functions" (RTConfig.java:63, identical on all branches).

### C2. ectoplasm: SpiritSpawnEggItem replaced by the loader's spawn egg classes (behaviour of the egg changes)
- 1.14.4 `item/SpiritSpawnEggItem.java:23-40` (own class): right-click always spawns at clicked pos offset by the face, `SpawnReason.SPAWN_EGG`, shrink 1 unless creative, no dispenser behaviour, does nothing on a spawner, no use on fluid.
- 1.16.5-1.20.1 `ModItems.java:376/384/379/381`: `ForgeSpawnEggItem(() -> SPIRIT, 0x000000, 0x0009F6, ...)`; 1.20.6/1.21.1: `DeferredSpawnEggItem` (same colours); 1.21.4/1.21.11 `ModItems.java:381/382`: plain vanilla `SpawnEggItem` (colours now only in the item model JSON).
- Vanilla egg logic therefore replaces the custom one: clicking a spawner block changes the spawner to Spirit, dispensers fire the egg, clicking a block with an empty collision shape (grass, water surface path) spawns at the block itself, not offset. SpiritEntity itself is present on ALL branches (`entity/SpiritEntity.java`); only the egg class is absent.
- Wiki: egg is not on the wiki page; low impact.

### C3. blazing_fire / blaze_and_steel: how the faster fire tick is implemented differs, delay may differ
- 1.14.4 `block/BlazingFireBlock.java:32-36`: `tickRate(IWorldReader)` returns 15 (vanilla 30). 1.14.4's own docs (02-pitfall-catalog K14) confirm the tickRate override alone already visibly speeds the fire.
- 1.16.5 and later: no override in `BlazingFireBlock`; `asm/AsmHandler.fireTickCooldown(rand, fire)` (1.16.5 AsmHandler.java:59-66, same on 1.18.2:61, 1.19.2:61, 1.20.1:63, 1.20.6/1.21.1/1.21.4/1.21.11:64) returns a flat `15` for Blazing Fire and `30 + rand.nextInt(10)` for vanilla fire. FireBlockTransformer.js (1.16.5-1.21.4) / `RTTransformers.FireBlock` (1.21.11) redirect `getFireTickDelay`.
- SUSPECTED consequence: in 1.14.4 vanilla `FireBlock.tick` schedules `tickRate + rand.nextInt(10)`, i.e. 15..24 ticks (avg 19.5); on 1.16.5+ it is exactly 15. Blazing fire would be ~30 % faster on 1.16.5+ than on the baseline. (Vanilla 1.14.4 source not available to me; the 30+rand(10) formula in the 1.16.5 hook comment suggests the old code added the same random term.)
- The other three Blazing Fire tweaks (flammability x4, die-out bound `age/2+1`, age growth `nextInt(8)`) are identical on every branch (AsmHandler boostFlammability / lowerDieOutBound / fasterAgeGrowth).

### C4. ectoplasm: Spirit lifetime expiry and /kill (SpiritEntity)
- 1.14.4/1.16.5 `SpiritEntity.java:70-72`: lifetime expiry calls `onKillCommand()` -> out-of-world damage -> real death (death animation), `/kill` also works.
- 1.18.2/1.19.2: `kill()` (still OUT_OF_WORLD damage, same).
- 1.20.1-1.21.11 `SpiritEntity.java` hurt/hurtServer: damage filter now whitelists only `MAGIC`, `INDIRECT_MAGIC`, `FELL_OUT_OF_WORLD`, creative player, and expiry uses `discard()` (code comment: "not kill(): its generic-kill damage is refused by hurt()"). Result: spirit just vanishes at expiry (no death animation / particles), and `/kill` (generic_kill) cannot kill a Spirit any more on 1.20.1+. Drops are unaffected (still none on expiry). Wiki fact "dies by itself after 20 s, leaving no drops" holds on all branches.

## SUSPECTED differences (probable, not fully proven from the repo alone)

### S1. spectre_key (dimension): vanilla "void start platform" no longer suppressed on 1.16.5+
- 1.14.4 `handler/spectre/SpectreChunkGenerator.java:61-70` overrides `carve`/`decorate` as no-ops precisely because `the_void` biome decorates a ~33x33 stone/cobble disc at y=3 around (8,3,8) (class javadoc lines 17-45; bug found by the user).
- 1.16.5 `SpectreChunkGenerator.java:45-63` and every later branch (1.18.2:50-102 ... 1.21.11:50-95) override only surface/base/carvers/mob spawn; none overrides `applyBiomeDecoration`/`func_230351_a_`, and I found no other handling (`git grep VOID_START` is empty). The dimension JSON uses biome `minecraft:the_void` (dimension/spectre.json on 1.20.1+, `ModDimensions.addToServer` before). If the_void still carries its start platform feature on those versions, the first player's cube (chunk 0,0) gets a stone slab at y=3 that sticks out 8 blocks around the cube and, since cube ceiling is at y=3, matches the original bug. Only visible in creative (non-creative players are snapped back into their own cube). Needs an in-game check.

### S2. spectre_key: return trip may build a nether portal on the baseline only
- 1.14.4 `AsmHandler.overrideMakePortal` (AsmHandler.java:361-370) only skips portal building when the DESTINATION is the Spectre dimension, although its javadoc (349-359) says both directions. Leaving Spectre therefore uses the vanilla `makePortal` if vanilla looks up a portal there (not verified). 1.16.5+ use `SpectreTeleporter` (1.16.5-1.20.1 `ITeleporter`, 1.21.1+ `DimensionTransition`/`TeleportTransition`) for both directions, no portal is ever built. Worth an in-game check on 1.14.4 (an extra portal frame near the stored return position would be a baseline bug, not a later-branch bug).

### S3. spectre_sapling (log/plank/leaf), spectre_tools: mining speed of Spectre wood and leaves on 1.18.2+
- 1.14.4/1.16.5: vanilla axe speed is material based (WOOD / PLANTS), so Spectre Log / Plank (`Material.WOOD`) are chopped fast by any axe; shears/sword on leaves likewise.
- 1.18.2+: tool speed is tag based. `data/minecraft/tags/blocks|block/mineable/axe.json` (identical on 1.18.2 ... 1.21.11) lists only block_of_sticks and the platforms, `mineable/shovel.json` only fertilized_dirt and colored_grass. `spectre_log`, `spectre_plank` (axe), and nothing for leaves/sapling exists (no `minecraft:leaves`, `minecraft:logs`, `hoe` tags either). So Spectre wood is mined at bare-hand speed with any axe incl. the Spectre Axe on 1.18.2+. (Leaf decay and "spectre_log not a log for leaf distance" are the same on all branches.) Vanilla internals from memory.

### S4. spectre_charger / spectre_coils: ROCK blocks need a pickaxe on 1.14.4 only
- `SpectreEnergyInjectorBlock` (hardness 3.0) and `SpectreCoilBlock` (0.3) use `Material.ROCK` on 1.14.4 (SpectreEnergyInjectorBlock.java:27, SpectreCoilBlock.java). In 1.14.x `Material.ROCK` requires the right tool for drops; from 1.16 on this is `requiresCorrectToolForDrops()` which none of these blocks sets (1.16.5 `Block.Properties.create(Material.ROCK)...`, 1.18.2+ `Properties.of(Material.STONE)...`, no tag). So hand-mined Injector/Coils drop on 1.16.5+, not on 1.14.4 (loot table `survives_explosion` only, identical on all branches). Vanilla internals from memory.

### S5. runic_dust: "solid top face" check is looser on 1.16.5+
- 1.14.4 `RuneDustItem.java:61`, `RunePatternItem.java:101`, `RuneBaseBlock.java:85`: `Block.hasSolidSide(state, world, pos, UP)` (full-face solid).
- 1.16.5: `Block.hasEnoughSolidSide(world, pos, UP)`; 1.18.2+: `Block.canSupportCenter(world, pos, UP)` (center-support check; excludes leaves). Fence/wall tops, and similar partial blocks, accept rune dust on 1.16.5+, but not on 1.14.4; leaves are accepted on 1.14.4 but not on 1.18.2+. Same check decides when an existing Rune Base breaks (neighborChanged).

### S6. escape_rope: landing block choice on 1.18.2+
- 1.14.4/1.16.5 `util/EscapeRopeHandler.java` (teleport scan, `y >= 0`): first block with `getBlockState(target).isSolid()` going down from the sky-visible position.
- 1.18.2+ (`EscapeRopeHandler.java:~108`): `canOcclude()` and the scan runs down to `getMinBuildHeight()` (`getMinY()` on 1.21.4+). Blocks that do not occlude (leaves, glass, ice and similar) are stepped through on 1.18.2+ and the player is placed on the first occluding block below. Also the scan lower bound is -64 instead of 0 (fallback to `nextPos+1` unaffected).
- Unchanged on all branches: needs sky-less location (`!canSeeSkyFromBelowWater`, hasSkyLight), 1200-tick use time (60 s), 20 durability, 4 checks/tick, 10000 visited-block limit, drop-rope-on-failure.

### S7. magnetic_enchantment: set of enchantable tools
- 1.14.4 `EnchantmentType.DIGGER` = ToolItem instances in 1.14 (pickaxe, axe, shovel; hoe is a plain Item then). 1.16.5: DIGGER (hoe is a ToolItem since 1.16). 1.18.2-1.20.6: `EnchantmentCategory.DIGGER` (Pickaxe/Axe/Shovel/Hoe = DiggerItem). 1.20.6/1.21.x: `ItemTags.MINING_ENCHANTABLE` / `#minecraft:enchantable/mining` (vanilla tag; may include shears and any modded item in the tag). Wiki says pickaxes, axes, shovels. Everything else (rarity RARE/weight 2, min cost 15, max 65, anvil cost 4, max level 1, MAINHAND, GLM applies on TOOL+THIS_ENTITY player, drops handed to the player) is identical.

### S8. ectoplasm: Moon-phase bonus in dimensions with fixed time (End) on 1.21.11
- 1.14.4 `RandomThings.java:~497-503`: bonus when `canBlockSeeSky && !isDaytime()`. 1.18.2-1.21.4: `canSeeSkyFromBelowWater && !isDay()` (same thing, fixed-time dims count as night). 1.21.11 `RandomThings.java:~72-73 of that block`: `!isBrightOutside()` with `MOON_BRIGHTNESS_PER_PHASE[(dayTime/24000 %8)]`; in the End (fixed time = noon) the sky-darken value may make `isBrightOutside()` true, so the full-moon bonus (+2 %) would not be applied in the End there, while it is applied on every other branch. Overworld unchanged. Edge case; needs an in-game check.

### S9. ectoplasm / spirits: Dragon breath no longer counts as magic damage on 1.20.1+
- 1.14.4/1.16.5/1.18.2/1.19.2 `SpiritEntity.hurt`: `source.isMagic()` (true for MAGIC, INDIRECT_MAGIC, DRAGON_BREATH). 1.20.1+: explicit `DamageTypes.MAGIC` / `INDIRECT_MAGIC` only. Dragon-breath clouds no longer hurt Spirits on 1.20.1+. Trivial.

### S10. spectre_sapling: ground check wider on 1.21.1+
- 1.14.4-1.20.6 `SpectreSaplingBlock.canSurvive`: `canSustainPlant(..., this)` (grass/dirt/podzol/farmland style). 1.21.1+: `TriState.isTrue() || default && (#minecraft:dirt || farmland)`; the DIRT tag also contains mud, moss block, rooted dirt, mycelium. Minor.

## Data-format / version-natural notes (not parity bugs of logic, but visible)

- position_filter: `dimension` NBT key is an int id on 1.14.4 (`PositionFilterItem.java:45,62,78`, tooltip prints e.g. "Dimension: 0") and a string `minecraft:overworld` from 1.16.5 on (`compound.getString("dimension")`, 1.16.5 PositionFilterItem.java:45). Tooltip text differs. All consumers (Portkey pickup hook RandomThings.java:~390 etc.) were changed in step. Old save data is not interchangeable. Data components in 1.20.6+ (custom_data) hold the same keys.
- spectre_key / SpectreHandler: saved return dimension `spectreDimension` int (1.14.4) vs string id (1.16.5+); `teleportPlayerBack` falls back to the Overworld when absent on 1.16.5+ (1.14.4: nothing happens if `spectrePosX` missing, same condition kept).
- Spectre dimension: 1.14.4 `SpectreDimension` (Dimension subclass, light table all 1.0, celestial angle 0.5, hasSkyLight false, fog 0.03/0.2/0.2, cloud height -5, findSpawn y 8) -> 1.16.5 `SpectreDimensionType` (fixed time 18000, no skylight, ambient light 1.0) + `SpectreRenderInfo` (same fog/cloud values) -> 1.18.2+ `dimension_type/spectre.json` (min_y 0, height 256, logical_height 256, ambient_light 1.0, fixed_time 18000, effects randomthings:spectre) + `dimension/spectre.json` (1.20.1+) / `ModDimensions.addToServer` (1.16.5-1.19.2). Biome the_void on every branch. 1.19.2+ add `monster_spawn_light_level 0-7` / `block_light_limit 0`; 1.21.11 replaces bed/respawn/fog with an `attributes` block (`bed_rule never`, fog #083333). `SpectreCube` (size 16 x (height+2) x 16, 2x2 core at 7..8, height cap 255) and `SpectreHandler` (cube per UUID, position counter +16, `checkPosition` snap-back, creative exempt, `getSpectreCubeFromPos` x range / z 0..16) are identical on all 9 branches (diff = renames only).
- The explicit `getSavedData().save()` after cube creation (1.14.4 SpectreHandler.java:153-154) is gone from 1.16.5 on; harmless because dimensions no longer unload (cube data is saved with the level).
- chunk_analyzer: scan runs from y=0 up to the surface on 1.14.4/1.16.5 and from `getMinBuildHeight()` (-64; `getMinY()` on 1.21.4+) on 1.18.2+, so counts on 1.18.2+ include deepslate / below-0 blocks (natural for the new world height). 10 columns/tick, WORLD_SURFACE+1 top, main-hand only, result stored under key `result` (custom_data on 1.20.6+) are identical.
- spectre_illuminator: placement scan box and relight volume use min/max build height on 1.18.2+ instead of 0..255 (world height); light value 14 over the whole chunk, orb centring speeds (0.05 / 0.03 per tick), one orb per chunk and +-2 block refusal radius identical. Light injection point: 1.14.4-1.19.2 `BlockGetter.getLightEmission(BlockPos)` (IBlockReaderTransformer); 1.20.1+ additionally redirects `BlockLightEngine` (BlockLightEngineTransformer / `RTTransformers.BlockLightEngine`); the 1.18.2/1.19.2 engine still goes through `BlockGetter.getLightEmission`, so equivalent.
- divining_rods: all geometry constants identical (11x11x11 around feet, 60 positions/tick, 160-tick indicators, size 0.1..0.3, main hand before off hand, colours/alpha 50). Detection is block TAG based, so block sets follow the loader's ore tags: forge:ores/* on 1.14.4-1.20.1, c:ores/* on 1.20.6+ (NeoForge). Deepslate ore variants are included from 1.18.2 on (they do not exist before); nether gold ore falls under the gold rod from 1.16.5 on if it is in the gold tag (loader data). Rod recipes and the vanilla rod's 7-ore list are identical.
- magic_hood: durability 55 (LEATHER head), defence/toughness/enchantability/sound/repair of CHAIN, rarity RARE on all branches (1.20.6 `ArmorItem.Type.HELMET.getDurability(5)`, 1.21.4 `ArmorMaterial(5, ...)`, 1.21.11 `humanoidArmor(...)` all = 5 x 11). Knockback resistance getter added in 1.16.5 (CHAIN = 0). Loot: simple_dungeon weight 5/100, village_weaponsmith 15/100, gated by `MagicHood` config on every branch (LootHandler.java:44-56 on 1.14.4, identical logic later). Nametag hook (`LivingRenderer/LivingEntityRenderer.canRenderName/shouldShowName`) present on every branch (JS coremod 1.14.4-1.21.4, Java transformer 1.21.11). Potion particles: `PotionColorCalculationEvent` (<=1.20.1) -> `EffectParticleModificationEvent.setVisible(false)` (1.20.6+), same outcome.

Class-name changes only: `SpectreDimension` (<=1.14.4) -> `SpectreDimensionType` (1.16.5 only; JSON from 1.18.2), `SpiritSpawnEggItem` (1.14.4 only, see C2), `MagneticEnchantment` (absent on 1.21.1+, see C1), new `SpectreTeleporter`/`SpectreRenderInfo` (1.16.5+; RenderInfo class removed on 1.21.11 in favour of dimension_type attributes).
